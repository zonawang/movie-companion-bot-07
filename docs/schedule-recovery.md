# 2026-10-31 當日場次讀取修正

使用者比較文心秀泰、長春國賓與澎湖 in89 的當日 18:00 後場次時，開眼預設頁回傳舊日期，部分請求回 HTTP 502。舊程式只讀「今天」首頁，未再讀指定日期頁；日期不符直接回未公告，HTTP／格式／網路錯誤也共用一則模糊訊息。

## 修正

- 當日首頁失敗或日期不符時，再讀同分館的 `YYYYMMDD/` 日期頁；兩個網址分開快取、合併同時請求，失敗冷卻三十秒，單次最多五秒。
- 不把舊日期當當日場次。保留 `sourceDate`、各次讀取狀態及安全的 HTTP／格式／網路錯誤分類；回覆可看到實際來源日期和失敗原因。
- 開眼沒有有效結果時，三個指定分館改用獨立核對的官方公開資料。其他已登錄分館仍使用既有來源，不任意跨館替代。
- 更新三間的官方連結，保留來源、查詢日期、18:00 篩選與不同版本。使用官方備援時，文字與 Flex 都明示實際來源及切換原因。

## 驗證

`test/schedule-recovery.test.mjs` 使用自製資料測日期頁恢復、舊資料加 502、格式失敗、官方分館／日期核對、跨年、凌晨日期、三館比較、匿名只讀請求與快取失效。

`npm run smoke:schedule:recovery` 使用真實官方公開資料與 Gemini／ADK，重現使用者原句，核對 18:00 過濾、三館來源、Flex 與 LINE `validate/reply`。使用記憶體資料庫，不傳送使用者訊息、不寫正式票匣。這是本次事件的即時診斷腳本；來源恢復成開眼時，需改以實際 provider 判讀，不把官方備援當作永久唯一來源。

正式 GCP 主機驗證時，秀泰來源回 HTTP 403（回應為 Blacklisted），本機可讀取並不代表正式主機也可讀。程式不改用代理或繞過拒絕；明示「官方網站拒絕伺服器存取」與官方入口，另兩間正常結果仍以 Flex 呈現。若要完全恢復秀泰自動場次，需取得對部署主機開放的官方資料來源或授權。即時 smoke 允許這個已知 403，但必須確認長春國賓與澎湖兩館恢復、秀泰不產生虛構場次、ADK 實際呼叫工具及 LINE schema 通過。
